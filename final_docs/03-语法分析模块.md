# 语法分析模块 (Parser)

## 模块职责

语法分析模块是编译流水线的第二阶段，负责将词法分析器输出的 Token 流按 Pascal-S 文法进行语法结构验证。模块使用 Bison 生成的 LALR(1) 解析器执行自底向上的移进-归约分析。如果语法正确，返回一个（当前为空壳的）AST 根节点；如果存在语法错误，通过错误恢复产生式尽可能多地收集错误信息。

语法分析模块同时承担一项关键的**桥接职责**：在 Flex（C 语言接口，返回 int 类型的 Bison Token 码）与 C++ 编译器其余部分（使用 `TokenType` 枚举和 `Token` 结构体）之间建立双向映射。

## Bison 桥接层数据流

下图展示了从 C++ 的 `vector<Token>` 到 Bison 的 `yyparse()` 再到 `ParserResult` 的完整数据转换流程。

![Bison 桥接层数据流图](picture/10-bison-bridge-flow.png)

桥接层的核心机制围绕四个全局状态变量展开：

```cpp
// parser_bison_bridge.cpp:10-13
const std::vector<Token>* g_tokens = nullptr;  // 输入 Token 流指针
size_t g_pos = 0;                               // 当前读取位置
Token g_lastToken;                              // 最近被 yylex() 返回的 Token（用于 yyerror 报错定位）
ParserResult* g_result = nullptr;               // 结果累积指针
```

数据流转路径：
1. `parseWithBison()` 设置 `g_tokens` 指向输入的 Token 向量，`g_pos = 0`，`g_result` 指向局部 `ParserResult`
2. 调用 `yyparse()` 启动 Bison LALR(1) 自动机
3. Bison 在每次需要下一个 Token 时回调 `yylex()`
4. `yylex()` 从 `g_tokens[g_pos++]` 取出下一个 Token，通过 `mapToken()` 将 `TokenType` 枚举转换为 Bison `T_XXX` 整型码，并记录到 `g_lastToken`
5. Bison 按文法规则进行移进-归约，直到输入结束或遭遇语法错误
6. 若归约到 `program` 产生式且到达 EOF，`yyparse()` 返回 0（成功）；否则返回非 0
7. 若遭遇语法错误，Bison 自动调用 `yyerror()`，从 `g_lastToken` 获取位置信息，构造 `ParseError(E201, ...)` 追加到 `g_result->errors`
8. `parseWithBison()` 检查返回码：若成功且无错误，则创建空的 `ProgramNode` 作为 `result.root`

## Token 映射体系

Flex 返回给 Bison 的是 int 类型的 Token 码，而编译器其余模块使用 `TokenType` 枚举。因此需要两个对称的映射函数：

![TokenType ↔ Bison Token 码双向映射图](picture/10-token-mapping-table.png)

上图展示了三个层面的对应关系：最左侧的 `TokenType (enum class)` 定义于 `token.h`，中间的 `Bison T_XXX (%token)` 宏定义于 Bison 生成的 `parser_bison.tab.h`，最右侧的 `Flex 正则` 定义于 `lexer_flex.l`。

双向映射的实现位置：

- **正向映射 `mapToken(TokenType → int)`**：定义于 `parser_bison_bridge.cpp:23-89`，将内部 `TokenType` 枚举转换为 Bison 期望的 `T_XXX` 整型码。此函数被 `yylex()` 调用，是 Token 从 C++ 世界进入 Bison C 世界的入口。
- **反向映射 `mapBisonTokenToInternal(int → TokenType)`**：定义于 `lexer.cpp:17-82`，将 Flex 返回的 Bison `T_XXX` 整型码转换回内部 `TokenType` 枚举。此函数被 `Lexer::tokenizeDetailed()` 调用，是 Token 从 Flex/Bison C 世界回到 C++ 世界的出口。

为什么需要双向映射？Flex 规则动作必须返回 Bison Token 码（因为 `yylex()` 的调用者是 Bison 生成的 `yyparse()`），但编译器下游模块不应依赖 Bison 的内部编号（这些编号是 Bison 自动分配的，可能在不同版本或配置下变化）。因此 `lexer.cpp` 在 Flex 返回后立即转换，对外只暴露 `TokenType`；而 `parser_bison_bridge.cpp` 在将 Token 喂给 Bison 前再转换回 Bison 码。

两个映射表必须保持严格的 1:1 对应关系，任何不对称都会导致解析器收到错误的 Token 类型。

## 文法设计

文件：`parser_bison.y`（343 行）

### Token 声明与优先级

```yacc
// parser_bison.y:8-21
%token T_UNKNOWN T_IDENTIFIER T_INTEGER T_REAL T_CHAR T_STRING T_BOOLEAN
%token T_PROGRAM T_CONST T_TYPE T_VAR T_PROCEDURE T_FUNCTION T_BEGIN T_END
%token T_IF T_THEN T_ELSE T_CASE T_WHILE T_REPEAT T_UNTIL T_FOR T_TO T_DOWNTO T_DO
%token T_READ T_READLN T_WRITE T_WRITELN
%token T_BREAK T_CONTINUE T_EXIT
%token T_RECORD T_ARRAY T_OF T_TYPE_INTEGER T_TYPE_REAL T_TYPE_BOOLEAN T_TYPE_CHAR
%token T_PLUS T_MINUS T_MULTIPLY T_DIVIDE T_DIV T_MOD T_AND T_OR T_NOT
%token T_ASSIGN T_EQUAL T_NOT_EQUAL T_LESS T_LESS_EQUAL T_GREATER T_GREATER_EQUAL
%token T_LPAREN T_RPAREN T_LBRACKET T_RBRACKET T_COMMA T_SEMICOLON T_COLON T_DOT T_DOTDOT

%left T_OR
%left T_PLUS T_MINUS
%left T_MULTIPLY T_DIVIDE T_DIV T_MOD T_AND
%right T_NOT
```

优先级声明定义了四层优先级（从低到高），每一层内部为左结合（`%left`）或右结合（`%right`）：

| 层级 | 声明 | 运算符 | 结合性 | 优先级 |
|------|------|--------|--------|--------|
| 1 | `%left T_OR` | `or` | 左结合 | 最低 |
| 2 | `%left T_PLUS T_MINUS` | `+`, `-` | 左结合 | |
| 3 | `%left T_MULTIPLY T_DIVIDE T_DIV T_MOD T_AND` | `*`, `/`, `div`, `mod`, `and` | 左结合 | |
| 4 | `%right T_NOT` | `not` | 右结合 | 最高 |

`not` 声明为右结合是因为 `not not x` 应解析为 `not (not x)`。`%left`/`%right` 声明不仅设置优先级，还解决了 Bison 的移进-归约冲突：当解析器在表达式中间遇到一个运算符时，它比较当前运算符与栈顶运算符的优先级来决定移进还是归约。

### 产生式层次结构

以下树形图展示了从顶层 `program` 到底层 `factor` 的完整产生式依赖关系。

![产生式层次结构图](picture/03-parser-grammar-tree.png)

图的根节点为 `program`，逐层展开揭示了 Pascal-S 文法的层次化结构：

#### 1. 程序结构（顶层）

```
program           → program_head program_body T_DOT          [parser_bison.y:25-26]
program_head      → T_PROGRAM T_IDENTIFIER T_LPAREN id_list T_RPAREN T_SEMICOLON
                  | T_PROGRAM T_IDENTIFIER T_LPAREN T_RPAREN T_SEMICOLON
                  | T_PROGRAM T_IDENTIFIER T_SEMICOLON       [parser_bison.y:28-32]
program_body      → const_declarations type_declarations var_declarations
                    subprogram_declarations compound_statement [parser_bison.y:34-37]
```

`program_head` 支持三种形式：带参数列表的程序头（`program demo(input, output)`）、空括号的程序头（`program demo()`）和最简单的无括号程序头（`program demo`）。`program_body` 严格遵循 Pascal-S 的声明顺序约束：常量声明 → 类型声明 → 变量声明 → 子程序声明 → 复合语句。

#### 2. 常量声明

```
const_declarations → ε | T_CONST const_declaration T_SEMICOLON   [parser_bison.y:44-46]
const_declaration  → T_IDENTIFIER T_EQUAL const_value
                   | const_declaration T_SEMICOLON T_IDENTIFIER T_EQUAL const_value
                   | const_declaration T_SEMICOLON error { yyerrok; }  [parser_bison.y:48-54]
const_value        → T_PLUS num | T_MINUS num | num
                   | T_CHAR | T_STRING | T_BOOLEAN
                   | T_IDENTIFIER | T_PLUS T_IDENTIFIER | T_MINUS T_IDENTIFIER [y:56-64]
num                → T_INTEGER | T_REAL                              [parser_bison.y:66-69]
```

关键设计：`const_declarations` 只声明**一个** `const_declaration`，多常量通过 `const_declaration` 内部的**左递归**实现——`const_declaration → const_declaration T_SEMICOLON T_IDENTIFIER T_EQUAL const_value`。这是 Pascal 语法的标准模式：关键字 `const` 只出现一次，后续常量定义用分号分隔。第三备选产生式 `const_declaration T_SEMICOLON error { yyerrok; }` 是错误恢复规则——当常量定义中间出现语法错误时，Bison 跳过错误直到分号，然后通过 `yyerrok` 宏恢复正常解析状态。

#### 3. 类型声明

```
type_declarations → ε | T_TYPE type_declaration T_SEMICOLON   [parser_bison.y:71-73]
type_declaration  → T_IDENTIFIER T_EQUAL type_spec
                  | type_declaration T_SEMICOLON T_IDENTIFIER T_EQUAL type_spec [y:75-78]
type_spec         → basic_type
                  | T_ARRAY T_LBRACKET periods T_RBRACKET T_OF type_spec   [y:80]
                  | T_RECORD record_body T_END                             [y:81]
                  | T_IDENTIFIER                                            [y:82]
basic_type        → T_TYPE_INTEGER | T_TYPE_REAL | T_TYPE_BOOLEAN | T_TYPE_CHAR [y:96-100]
periods           → period | periods T_COMMA period               [parser_bison.y:88-91]
period            → const_value T_DOTDOT const_value               [parser_bison.y:93-95]
```

类型体系中最值得注意的是数组类型：`T_ARRAY T_LBRACKET periods T_RBRACKET T_OF type_spec` 中的 `type_spec` 递归引用自身，从而支持**多维数组**（如 `array[1..10, 1..5] of integer` 先解析外层 `array[1..10, 1..5] of type_spec`，内层的 `type_spec` 自身又可被解析为 `integer`）。

`periods → periods T_COMMA period` 的左递归结构支持逗号分隔的多维下标范围。

#### 4. 变量声明

```
var_declarations  → ε | T_VAR var_declaration T_SEMICOLON      [parser_bison.y:110-112]
var_declaration   → id_list T_COLON type_spec
                  | var_declaration T_SEMICOLON id_list T_COLON type_spec  [y:114-116]
                  | var_declaration T_SEMICOLON error { yyerrok; }         [y:118]
id_list           → T_IDENTIFIER | id_list T_COMMA T_IDENTIFIER  [parser_bison.y:39-42]
```

`id_list` 的左递归支持逗号分隔的多变量声明（如 `a, b, c: integer`），而 `var_declaration` 的左递归支持分号分隔的多组变量声明。

#### 5. 子程序（过程/函数）

```
subprogram_declarations → ε
                        | subprogram_declarations subprogram_declaration T_SEMICOLON [y:121-124]
subprogram_declaration  → subprogram_head subprogram_body            [parser_bison.y:126-128]
subprogram_head → T_FUNCTION T_IDENTIFIER formal_parameter T_COLON basic_type T_SEMICOLON
                | T_PROCEDURE T_IDENTIFIER formal_parameter T_SEMICOLON [y:130-133]
formal_parameter → ε | T_LPAREN parameter_lists T_RPAREN | T_LPAREN T_RPAREN [y:135-138]
parameter_lists  → parameter_list | parameter_lists T_SEMICOLON parameter_list [y:140-143]
parameter_list   → var_parameter | value_parameter                   [parser_bison.y:145-148]
var_parameter    → T_VAR value_parameter                             [parser_bison.y:150-152]
value_parameter  → id_list T_COLON basic_type                        [parser_bison.y:154-156]
subprogram_body  → const_declarations type_declarations var_declarations compound_statement [y:158-161]
```

子程序文法揭示了 Pascal-S 的几个关键语义约束：
- `subprogram_body` 复用了 `const_declarations` / `type_declarations` / `var_declarations` 产生式，但**不包含** `subprogram_declarations`——这意味着 Pascal-S 的子程序体中可以有自己的局部常量/类型/变量声明，但**不能嵌套定义子程序**（这是 Pascal-S 教学子集的限制；标准 Pascal 允许嵌套）。
- `var_parameter → T_VAR value_parameter`：VAR 引用参数在语法层通过前置关键字 `var` 区分，语义层再根据 `byRef` 标记做引用语义处理。
- `formal_parameter` 的三条备选规则分别处理：无括号（空参数列表）、有空括号（`()`）、有括号含参数列表。

#### 6. 语句

```
compound_statement → T_BEGIN statement_list_opt T_END              [parser_bison.y:163-165]
statement_list_opt → ε | statement_list                            [parser_bison.y:167-170]
statement_list     → stmt
                   | statement_list T_SEMICOLON stmt                [parser_bison.y:172-174]
                   | statement_list error T_SEMICOLON { yyerrok; }  [parser_bison.y:175]

stmt → identifier_stmt    — 赋值语句 / 过程调用（通过后续 Token 是否为 Assign 或 LParen 区分）
     | compound_statement — begin...end 块
     | if_stmt            — if...then...else
     | case_stmt          — case...of...end
     | while_stmt         — while...do
     | repeat_stmt        — repeat...until
     | for_stmt           — for...to/downto...do
     | read_stmt          — read/readln
     | write_stmt         — write/writeln
     | break_stmt         — break
     | continue_stmt      — continue
     | exit_stmt          — exit
     | error { yyerrok; } — 错误恢复：跳过无法识别的语句
     | /* empty */        — 空语句（允许多余的分号）                [parser_bison.y:178-199]
```

语句产生式的设计体现了几个重要考量：
- 空语句备选（`/* empty */`）允许连续分号（`a := 1;; b := 2`）和 begin 后紧跟 end（`begin end`）的情况。
- `identifier_stmt` 的歧义（赋值 vs 过程调用）在语法层不做区分——两种形式都以标识符开头，Bison 通过后续 Token 的前瞻（`:=` vs `(`）自动选择正确的归约路径。这是 LALR(1) 解析器的典型能力。
- `statement_list` 的错误恢复规则 `statement_list error T_SEMICOLON { yyerrok; }` 使解析器在遭遇语句级别错误时跳过错误内容直到下一个分号，然后继续解析后续语句。

#### 7. 表达式（带优先级）

表达式子体系是 Bison 文法中最复杂、最精巧的部分，通过产生式嵌套层次与 `%left`/`%right` 优先级声明共同保证正确的运算符优先级和结合性。

![表达式优先级层级图](picture/03-parser-precedence.png)

```
expression       → simple_expression
                 | simple_expression relop simple_expression      [parser_bison.y:292-296]
relop            → T_EQUAL | T_NOT_EQUAL | T_LESS | T_LESS_EQUAL
                 | T_GREATER | T_GREATER_EQUAL                     [parser_bison.y:298-308]
simple_expression → term | simple_expression addop term           [parser_bison.y:310-313]
addop            → T_PLUS | T_MINUS | T_OR                        [parser_bison.y:315-319]
term             → factor | term mulop factor                     [parser_bison.y:321-324]
mulop            → T_MULTIPLY | T_DIVIDE | T_DIV | T_MOD | T_AND  [parser_bison.y:326-332]
factor           → num | variable | T_IDENTIFIER T_LPAREN expr_list_opt T_RPAREN
                 | T_LPAREN expression T_RPAREN
                 | T_NOT factor | T_MINUS factor | T_PLUS factor
                 | T_CHAR | T_BOOLEAN                              [parser_bison.y:334-340]
```

表达式优先级从低到高共 4 层：

| 层级 | 产生式 | 运算符 | 结合性 | C 等价 |
|------|--------|--------|--------|--------|
| 1 | `expression → simple_expression relop simple_expression` | `=`, `<>`, `<`, `<=`, `>`, `>=` | 无结合性（关系运算符不可链式比较） | `a == b` |
| 2 | `simple_expression → simple_expression addop term` | `+`, `-`, `or` | 左 | `a + b - c` |
| 3 | `term → term mulop factor` | `*`, `/`, `div`, `mod`, `and` | 左 | `a * b / c` |
| 4 | `factor → T_NOT factor \| T_MINUS factor` | `not`, `-`（一元） | 右 | `not not x` |

关系运算符（relop）不声明结合性——这意味着 `a = b = c` 这样的链式比较在 Pascal-S 中是语法错误（不像 C 那样是合法的）。这是通过 Bison 中关系运算符不声明 `%left` 或 `%right` 来实现的——Bison 遇到 `expression relop expression relop expression` 时会产生移进-归约冲突，其默认行为（移进优先）导致解析为 `(a = b) = c` 的形式，这在语义分析阶段会被类型检查拒绝。

`factor` 中的一元运算符 `T_NOT factor` 和 `T_MINUS factor` 利用产生式嵌套实现右结合性（`not not x` → `not (not x)`），同时赋予一元运算符最高优先级（`not a + b` → `(not a) + b`）。

### 错误恢复策略

Bison 文法中嵌入了 4 处错误恢复产生式，使解析器在遭遇语法错误时能跳过错误内容并继续解析后续结构，从而在一次编译器运行中报告尽可能多的语法错误：

```yacc
// parser_bison.y:54 — 常量声明内部错误恢复
const_declaration: const_declaration T_SEMICOLON error { yyerrok; }

// parser_bison.y:118 — 变量声明内部错误恢复
var_declaration: var_declaration T_SEMICOLON error { yyerrok; }

// parser_bison.y:175 — 语句列表错误恢复
statement_list: statement_list error T_SEMICOLON { yyerrok; }

// parser_bison.y:196 — 单语句错误恢复
stmt: error { yyerrok; }
```

每处错误恢复的核心是 `yyerrok` 宏——它告诉 Bison 错误恢复已完成，可以恢复正常解析。`error` 是 Bison 的特殊通配 Token，匹配任意 Token 序列直到遇到一个可同步的 Token（在上下文中的合法后继）。

## Bison 桥接层实现

文件：`parser_bison_bridge.cpp`（127 行）

### yylex() —— Token 供给

```cpp
// parser_bison_bridge.cpp:92-100
extern "C" int yylex(void) {
    if (!g_tokens || g_pos >= g_tokens->size()) {
        return 0;  // 返回 0 表示 EOF
    }
    const Token& token = (*g_tokens)[g_pos++];
    g_lastToken = token;     // 保存位置用于 yyerror 报错
    return mapToken(token.type);  // TokenType → Bison T_XXX
}
```

`yylex()` 的核心逻辑非常简单：从全局 Token 向量中按序取出，通过 `mapToken()` 转换类型码，记录到 `g_lastToken`。当 `g_pos` 超过向量大小时返回 0，通知 Bison 已到达输入末尾。注意这里**不会**跳过 `EndOfFile` 哨兵——它会被转换为 0（EOF），但在此之前的所有 Token（包括最后一个有效 Token）都会被正常返回。

### yyerror() —— 错误报告

```cpp
// parser_bison_bridge.cpp:102-105
extern "C" void yyerror(const char* msg) {
    const SourcePosition pos = g_lastToken.pos;
    addParseError("E201", std::string("Syntax error: ") + msg, pos);
}
```

Bison 在检测到语法错误时自动调用 `yyerror()`，传入描述性错误消息（通常为 `"syntax error"`）。桥接层将其封装为 `ParseError`（错误码 E201），并使用 `g_lastToken.pos` 报告最近成功读取的 Token 的位置（这是 LALR(1) 解析器错误定位的标准做法——错误通常发生在最近读入的 Token 之后）。

### parseWithBison() —— 公开接口

```cpp
// parser_bison_bridge.cpp:107-126
ParserResult parseWithBison(const std::vector<Token>& tokens) {
    ParserResult result;
    g_tokens = &tokens;
    g_pos = 0;
    g_lastToken = Token{TokenType::EndOfFile, "<EOF>", {1, 1}};
    g_result = &result;

    const int rc = yyparse();
    if (rc != 0 && result.errors.empty()) {
        // Bison 返回非 0 但没有通过 yyerror 报告的错误（罕见情况）
        result.errors.push_back(ParseError{"E299", "Syntax analysis failed.", g_lastToken.pos});
    }
    if (result.errors.empty()) {
        // M3 minimal AST placeholder
        result.root = std::make_shared<ProgramNode>();
    }

    g_tokens = nullptr;   // 清理全局状态，防止悬空指针
    g_result = nullptr;
    return result;
}
```

函数执行流程：设置全局指针 → 调用 `yyparse()` → 检查返回码 → 若成功则创建占位 AST → 清理全局状态 → 返回结果。

当前 AST 仅定义了最基础的节点类型框架。缺失的内容包括但不限于：
- **运算符类型**：`ExpressionNode` 没有字段记录是加法、乘法还是比较
- **标识符/字面量值**：没有字段存储标识符名称或字面量的值

## 数据流

```
Parser::parse(tokens)
  → parseWithBison(tokens)
    → 设置全局 g_tokens / g_pos / g_result
    → yyparse()
        ├─ → yylex() × N: TokenType → mapToken() → T_XXX
        ├─ → yyerror() × M: 构造 ParseError(E201)
        └─ 移进-归约 LALR(1) 自动机
    → 检查返回码: rc == 0 && errors.empty() → 创建 ProgramNode
    → 清理全局状态
    → ParserResult {
        errors: [ParseError(E201), ...]   // 语法错误列表
        root: shared_ptr<ProgramNode>      // 成功时为占位空节点，失败时为 nullptr
      }
```
