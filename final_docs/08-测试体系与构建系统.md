# 测试体系与构建系统

## 构建系统 (CMake)

文件：`CMakeLists.txt`（200 行）

### 项目配置

```cmake
# CMakeLists.txt:1-8
cmake_minimum_required(VERSION 3.16)
project(pascc LANGUAGES C CXX)
set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_CXX_EXTENSIONS OFF)
enable_testing()
```

`CMAKE_CXX_EXTENSIONS OFF` 确保编译器不启用 GNU 扩展，保证代码的严格 C++17 标准兼容性。

### Flex/Bison 集成

Flex 和 Bison 的编译集成是 CMake 构建系统中最具技术含量的部分，下图展示了自定义命令之间的依赖关系。

![CMake Flex/Bison 生成依赖图](picture/10-cmake-flex-bison-build.png)

```cmake
# CMakeLists.txt:10-37
# 查找 Flex/Bison 可执行文件（Windows 上为 win_flex/win_bison）
find_program(BISON_EXECUTABLE NAMES win_bison bison)
find_program(FLEX_EXECUTABLE NAMES win_flex flex)

# Bison 自定义命令: parser_bison.y → parser_bison.tab.c + parser_bison.tab.h
add_custom_command(
    OUTPUT ${BISON_OUTPUT_C} ${BISON_OUTPUT_H}
    COMMAND ${BISON_EXECUTABLE} -d -o ${BISON_OUTPUT_C}
            ${CMAKE_CURRENT_SOURCE_DIR}/src/parser_bison.y
    DEPENDS ${CMAKE_CURRENT_SOURCE_DIR}/src/parser_bison.y
)

# Flex 自定义命令: lexer_flex.l → lexer_flex.cpp + lexer_flex.h
add_custom_command(
    OUTPUT ${FLEX_OUTPUT_C} ${FLEX_OUTPUT_H}
    COMMAND ${FLEX_EXECUTABLE} --header-file=${FLEX_OUTPUT_H}
            -o ${FLEX_OUTPUT_C} ${CMAKE_CURRENT_SOURCE_DIR}/src/lexer_flex.l
    DEPENDS ${CMAKE_CURRENT_SOURCE_DIR}/src/lexer_flex.l ${BISON_OUTPUT_H}
    # Flex 依赖 Bison 生成的头文件（需要 T_XXX Token 编号宏）
)
```

关键的依赖链：`parser_bison.y` → `parser_bison.tab.h` → `lexer_flex.l` → `lexer_flex.cpp`。Flex 的编译必须等待 Bison 生成的头文件就绪，因为 `lexer_flex.l` 中 `#include "parser_bison.tab.h"` 需要 `T_IDENTIFIER` 等 Token 编号宏。

### 目标架构

CMake 定义了两个静态库和 13 个可执行目标，下图展示了它们之间的链接依赖关系。

![CMake 目标依赖图](picture/08-cmake-target-graph.png)

```
libraries:
  parser_bison      — Bison 生成的语法分析器 + 桥接层 (parser_bison_bridge.cpp)
  lexer_frontend    — Flex 生成的词法分析器 + 封装层 (lexer.cpp)

executables:
  pascc             — 编译器主程序（5 个源文件 + 链接两个库）
  *_tests           — 12 个测试可执行文件
```

```cmake
# CMakeLists.txt:39-53 — parser_bison 库
add_library(parser_bison
    ${BISON_OUTPUT_C}                   # Bison 生成的 .tab.c
    src/parser_bison_bridge.cpp          # yylex/yyerror 桥接
)
target_include_directories(parser_bison PUBLIC include ${CMAKE_CURRENT_BINARY_DIR})

# CMakeLists.txt:49-60 — lexer_frontend 库
add_library(lexer_frontend
    src/lexer.cpp                        # Lexer 类封装
    ${FLEX_OUTPUT_C}                     # Flex 生成的 .cpp
)
# Windows: YY_NO_UNISTD_H 宏确保跨平台编译 (unistd.h 在 MSVC 上不存在)
if(WIN32)
    target_compile_definitions(lexer_frontend PRIVATE YY_NO_UNISTD_H=1)
endif()

# CMakeLists.txt:62-71 — pascc 主程序
add_executable(pascc
    src/main.cpp
    src/compiler_driver.cpp
    src/code_generator.cpp
    src/parser.cpp
    src/semantic_declaration.cpp
)
target_link_libraries(pascc PRIVATE parser_bison lexer_frontend)

# CMakeLists.txt:74-76 — Linux 静态链接
if(NOT WIN32)
    target_link_options(pascc PRIVATE -static -static-libstdc++ -static-libgcc)
endif()
```

## 测试体系总览

测试体系遵循经典的"测试金字塔"分层设计，共 12 个测试目标，分为 4 个层级。下图以金字塔形式展示了这一分层结构。

![测试分层金字塔](picture/08-test-hierarchy.png)

### 层级 1：单元测试（底层，2 个测试，不依赖 Flex/Bison）

这些测试不链接任何 CTest 外的库，仅测试纯数据结构的逻辑正确性：

| 测试名 | 源文件 | 测试内容 |
|--------|--------|---------|
| `semantic_tableset_tests` | `tests/semantic_tableset_tests.cpp` | `TableSet::insert()` 插入、`searchEntry()` 链式查找、`prevSet_` 作用域链等核心数据结构的正确性 |
| `semantic_typepool_tests` | `tests/semantic_typepool_tests.cpp` | `BuiltinTypePool` 的创建、`findByName()` 查询、`installInto()` 注入 |

```cmake
# CMakeLists.txt:118-124
add_executable(semantic_tableset_tests tests/semantic_tableset_tests.cpp)
target_include_directories(semantic_tableset_tests PRIVATE include)
# 注意：不链接任何库，仅 include 头文件即可编译
```

### 层级 2：词法/语法模块测试（4 个测试，链接 Flex/Bison 生成库）

| 测试名 | 源文件 | 链接 | 测试内容 |
|--------|--------|------|---------|
| `lexer_smoke_tests` | `tests/lexer_smoke_tests.cpp` | parser_bison + lexer_frontend | 冒烟测试：验证基本 Token 识别和关键字映射正确性 |
| `lexer_tests` | `tests/lexer_tests.cpp` | parser_bison + lexer_frontend | 词法详细测试：关键字全覆盖、整数/实数/字符字面量、单行/块注释、词法错误（E106/E107/E110） |
| `parser_tests` | `tests/parser_tests.cpp` | parser_bison + lexer_frontend | 语法解析测试：各种程序结构（程序头、常量、变量、各种语句）的 Bison 解析验证 |
| `bison_parser_tests` | `tests/bison_parser_tests.cpp` | parser_bison + lexer_frontend | Bison 解析器专项测试：合并冲突验证、错误恢复功能 |

### 层级 3：语义分析模块测试（4 个测试，链接语义分析模块）

| 测试名 | 源文件 | 额外链接 | 测试内容 |
|--------|--------|---------|---------|
| `semantic_declaration_tests` | `tests/semantic_declaration_tests.cpp` | parser.cpp + semantic_declaration.cpp | 声明检查：同作用域重定义（S101）、作用域嵌套、常量/变量声明 |
| `semantic_usage_tests` | `tests/semantic_usage_tests.cpp` | parser.cpp + semantic_declaration.cpp | 标识符使用检查：未定义标识符使用（S103）、已定义标识符正常使用 |
| `semantic_expression_tests` | `tests/semantic_expression_tests.cpp` | parser.cpp + semantic_declaration.cpp | 表达式类型检查：各运算符类型约束（isNumeric/isAssignable）、promoteNumeric |
| `semantic_param_tests` | `tests/semantic_param_tests.cpp` | parser.cpp + semantic_declaration.cpp | 参数类型匹配：值参数兼容性、VAR 参数严格匹配、参数数量匹配（S202） |

### 层级 4：端到端集成测试（顶层，2 个测试，链接所有模块）

| 测试名 | 源文件 | 额外链接 | 测试内容 |
|--------|--------|---------|---------|
| `semantic_gate_tests` | `tests/semantic_gate_tests.cpp` | compiler_driver.cpp + code_generator.cpp + parser.cpp + semantic_declaration.cpp | 端到端语义门控：在系统临时目录写 `.pas` 临时文件 → 完整调用 `CompilerDriver::run()` → 验证退出码和输出 `.c` 文件内容 |
| `codegen_template_tests` | `tests/codegen_template_tests.cpp` | code_generator.cpp | 代码生成模板测试：对 `samples/*.pas` 调用 `CodeGenerator::generateTemplate()` 生成 C 代码，检查 C 输出中是否包含特定翻译模式 |

## 测试命名约定

每个测试函数内的断言使用描述性名称 `"module_feature_detail"` 格式：

- `codegen_template_basic_ok`
- `codegen_controlflow_while`
- `gate_semantic_fail_exit_code_9`

通过 `expect(condition, testName)` 辅助函数统一输出 `[PASS]` / `[FAIL]` 格式的测试结果。
