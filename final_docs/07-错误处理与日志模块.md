# 错误处理与日志模块

## 模块职责

错误处理与日志模块是整个编译器的"基础设施"层，为所有其他模块提供统一的错误码定义、进程退出码转换和格式化控制台日志输出功能。模块的设计哲学是极简主义——两个头文件共 38 行代码，全部实现为 inline 函数，零外部依赖，零编译开销。

## 文件结构

| 文件 | 行数 | 职责 |
|------|------|------|
| `error_codes.h` | 21 | `ErrorCode` 枚举定义（11 种退出状态）+ `toExitCode()` 转换函数 |
| `log.h` | 17 | 控制台日志工具函数：`info()`（stdout）、`error()`（stderr）|

## ErrorCode 枚举

文件：`error_codes.h`

```cpp
// error_codes.h:4-15
enum class ErrorCode {
    Ok = 0,                // 编译成功，一切正常
    Usage = 2,             // 命令行参数使用错误（argc ≠ 3 或 argv[1] ≠ "-i"）
    InvalidExtension = 3,  // 输入文件不是 .pas 后缀
    InputNotFound = 4,     // 输入文件不存在或无法读取
    InputUnreadable = 5,   // （预留）输入文件不可读 — 当前未被任何代码使用
    OutputCreateFailed = 6,// 无法创建输出 .c 文件（目录权限不足或磁盘满）
    LexicalError = 7,      // 词法分析阶段检测到错误
    SyntaxError = 8,       // 语法分析阶段检测到错误
    SemanticError = 9,     // 语义分析阶段检测到错误
    GenerationError = 10,  // 代码生成阶段失败
};

// error_codes.h:17-19
inline int toExitCode(ErrorCode code) {
    return static_cast<int>(code);  // 枚举值即进程退出码
}
```

退出码的设计遵循了语义化的编号规则：0 为成功，2-6 为驱动层错误（输入/输出/参数），7-10 为四个编译阶段各自的失败码。`toExitCode()` 直接取枚举的底层 int 值，因为枚举值已按进程退出码的需求精心编排。

## 日志模块

文件：`log.h`（17 行）

```cpp
// log.h:8-15
namespace logutil {

inline void info(const std::string& msg) {
    std::cout << "[INFO] " << msg << std::endl;     // 标准输出
}

inline void error(const std::string& code, const std::string& msg) {
    std::cerr << "[" << code << "] " << msg << std::endl;  // 标准错误
}

}  // namespace logutil
```

极简设计的所有要点：

- **全部 inline**：两个函数都在头文件中直接定义，无需链接单独的日志库。
- **输出分流**：`info()` 写入 stdout（供用户查看的正常信息），`error()` 写入 stderr（供管道/脚本捕获的错误信息）。这种分流使得 Unix 风格的 `pascc -i input.pas 2>errors.log` 可以正常使用。
- **格式一致**：`info()` 输出 `[INFO] msg`，`error()` 输出 `[CODE] msg`，统一的前缀格式便于机器解析。
- **无依赖**：`logutil` namespace 不引用任何项目内的其他头文件，任何模块都可以独立 include `log.h` 使用。

## 错误上报模式

所有编译阶段的错误上报遵循统一的三步模式：

```
1. 模块内部操作时累积错误到 result.errors 向量
2. CompilerDriver 在每个阶段后检查 errors.empty() 判断是否通过
3. 若失败:
   a. 遍历 errors 逐条调用 logutil::error(code, "(line:col) " + message)
   b. 输出汇总 logutil::error("EX99", "Stage failed with N error(s).")
   c. return toExitCode(ErrorCode::XxxError)
```

以词法阶段的错误上报为例：

```cpp
// compiler_driver.cpp:33-39
if (!lexResult.errors.empty()) {
    for (const auto& err : lexResult.errors) {
        logutil::error(err.code,
            "(" + std::to_string(err.pos.line) + ":"
                + std::to_string(err.pos.column) + ") "
                + err.message);
    }
    logutil::error("E199",
        "Lexical analysis failed with "
        + std::to_string(lexResult.errors.size()) + " error(s).");
    return toExitCode(ErrorCode::LexicalError);
}
```

这种统一模式确保了错误输出的一致性——无论错误来自哪个模块，用户看到的格式都是 `[CODE] (line:col) message`。
