## 01 — 总体架构设计

### 图 1.1：编译流水线架构图

- **插入位置**：`## 编译流水线` 章节，替换现有的 ASCII art 框图
- **图类型**：数据流图 / 管道图
- **内容**：
  - 四个矩形框从左到右排列：词法分析 → 语法分析 → 语义分析 → 代码生成
  - 框内标注模块名称和输入/输出格式（`.pas 源码` → `Token 流` → `AST` → `校验通过` → `.c 源码`）
  - 框之间用粗箭头连接，箭头旁标注数据结构（Token 流、AST、SemanticResult）
  - 在最下方画一条水平横线，标注"CompilerDriver 编排"，用虚线向上连接到四个阶段
- **推荐工具**：draw.io（免费桌面版）或 Excalidraw
- **文件**：`images/01-architecture-pipeline.png`
- **具体画法**：
  1. 打开 draw.io，新建空白框图
  2. 拖入 4 个"Process"形状（圆角矩形），等距排列
  3. 文字：`词法分析\n(Lexer)`、`语法分析\n(Parser)`、`语义分析\n(Semantic)`、`代码生成\n(Codegen)`
  4. 用"箭头"连接相邻框，在箭头上方添加文字标签
  5. 在底部拖入一个大矩形，设为虚线边框，文字 `CompilerDriver::run()`
  6. 用虚线从底部矩形连接到 4 个阶段的底部
  7. 导出 PNG，分辨率 2x

### 图 1.2：模块-文件对应关系图

- **插入位置**：`## 模块划分与文件映射` 表格之后
- **图类型**：分层架构图
- **内容**：
  - 三层结构：头文件层 (include/)、实现层 (src/)、生成层 (Flex/Bison)
  - 每个模块用不同颜色标识（词法=蓝、语法=绿、语义=橙、代码生成=紫、驱动=灰）
  - 连线表示 include/编译依赖关系
- **推荐工具**：PlantUML（纯文本绘图，可直接嵌入 markdown）或 draw.io
- **文件**：`images/01-architecture-modules.png`
- **具体画法**（PlantUML）：
  ```plantuml
  @startuml
  component "include/" as inc
  component "src/" as src
  component "Flex/Bison" as gen
  inc -- src
  gen -- src
  @enduml
  ```

  粘贴到 [plantuml.com](https://www.plantuml.com) 在线渲染导出 PNG。

## 02 — 词法分析模块

### 图 2.1：Token 类型分类图

- **插入位置**：`### 分类一览` 段落，替换 ASCII 树形图
- **图类型**：树形分类图 / 思维导图
- **内容**：
  - 根节点：`TokenType (enum)`
  - 一级分支：特殊、字面量、关键字(KwXxx)、运算符、界符
  - 二级展开：每类下列举 3-5 个典型值，省略号表示更多
  - 关键字分支下再分组：程序结构、子程序、控制流、I/O、类型
- **推荐工具**：draw.io 的"思维导图"模式
- **文件**：`images/02-lexer-token-tree.png`
- **具体画法**：
  1. draw.io → 新建 → 选择"Mind Map"模板
  2. 中心节点：`TokenType`
  3. 5 个子节点展开，关键字节点再展开一层
  4. 用不同颜色标识 5 个大类
  5. 导出 PNG

### 图 2.2：Flex 扫描流程图

- **插入位置**：`## Flex 规则设计` 章节开头
- **图类型**：状态转移图
- **内容**：
  - 初始状态 INITIAL：空白/换行（自循环）、`{` → COMMENT 状态、运算符/界符 → 直接匹配返回、字面量 → 匹配返回、标识符 → 查关键字表
  - COMMENT 状态：`}` → 回到 INITIAL、`{` → 报错 E106、EOF → 报错 E107、其他字符 → 自循环
  - 每条边标注匹配的正则表达式
- **推荐工具**：Graphviz (DOT 语言)
- **文件**：`images/02-lexer-flex-states.png`
- **具体画法**（Graphviz DOT）：
  ```dot
  digraph {
    rankdir=LR;
    INITIAL -> COMMENT [label="\"{\""];
    COMMENT -> INITIAL [label="\"}\""];
    COMMENT -> COMMENT [label="其他字符"];
    COMMENT -> ERROR [label="\"{\"", color=red];
    COMMENT -> ERROR2 [label="EOF", color=red];
    INITIAL -> RETURN [label="标识符/关键字"];
    INITIAL -> RETURN2 [label="运算符/界符"];
    INITIAL -> RETURN3 [label="字面量"];
  }
  ```

  用 `dot -Tpng 02-lexer-flex-states.dot -o images/02-lexer-flex-states.png` 渲染。

## 03 — 语法分析模块

### 图 3.1：产生式层次结构图

- **插入位置**：`### 产生式总览` 开头
- **图类型**：语法图 / 树形产生式依赖图
- **内容**：
  - 从 `program` 出发，逐层展开到子规则
  - 顶层：`program → program_head + program_body + DOT`
  - `program_body` → 5 个组成部分（const/type/var/subprogram/compound）
  - `stmt` → 9 种语句类型分支
  - `expression` → simple_expression → term → factor 链条
  - 用不同粗细/颜色区分顶层结构和底层表达式
- **推荐工具**：draw.io 或 Excalidraw
- **文件**：`images/03-parser-grammar-tree.png`
- **具体画法**：
  1. 竖排布局，根节点在最上
  2. 每层用框包住，标注非终结符名
  3. 层间用箭头连接，标注分隔符（`;` / `.` 等）
  4. 底部用虚线框突出 `expression` 子体系（因涉及优先级）

### 图 3.2：表达式优先级层级图

- **插入位置**：`#### 7. 表达式（带优先级）` 段落
- **图类型**：优先级金字塔 / 层级图
- **内容**：
  - 从上到下 4 层（优先级从低到高）
  - OR 层 → + / - 层 → * / / div mod and 层 → NOT / 一元运算符
  - 每层标注产生式名称、关联的 Token
  - 最底层标注 factor（字面量、标识符、括号、调用）
- **推荐工具**：draw.io
- **文件**：`images/03-parser-precedence.png`
- **具体画法**：
  1. 画 4 个横向矩形，自下而上堆叠
  2. 从下到上分别标注：`Factor`、`Term (mulop)`、`Simple Expr (addop)`、`Expression (relop)`
  3. 在每个矩形内标注运算符：`[NOT, - (unary)]`、`[*, /, DIV, MOD, AND]`、`[+, -, OR]`
  4. 顶部标注 `[=, <>, <, <=, >, >=]`
  5. 用括号从低到高标注"优先级递增"

## 04 — 语义分析模块

### 图 4.1：作用域链结构图

- **插入位置**：`### ScopeStack` 段落之后
- **图类型**：链表/层级图
- **内容**：
  - 3 个矩形纵向排列，表示作用域栈
  - 最上层：`global`（含 builtin types + 全局变量/例程符号）
  - 中层：`procedure foo`（含局部变量 + 参数符号）
  - 下层：`function bar`（含局部变量 + 参数 + 返回值）
  - 每层用 `prevSet_` 指针指向上层（向左的弧形箭头）
  - 右侧标注 `ScopeStack::current()` 指向栈顶
- **推荐工具**：draw.io
- **文件**：`images/04-semantic-scope-chain.png`
- **具体画法**：
  1. 纵向排列 3 个大方框，从左到右递减宽度（体现嵌套）
  2. 每个框内部用小字列出示例符号
  3. 用弯曲箭头从每个框指向上一层
  4. 最右侧画一个箭头指向最底层的框，标注 `current()`

### 图 4.2：类型检查决策树

- **插入位置**：`### 类型检查规则` 段落
- **图类型**：决策流程图
- **内容**：
  - 以二分检查为核心的分支图
  - `isNumericType()` → `promoteNumeric()` 分支
  - `isAssignable()` → 同类型 pass / Int→Real widen pass / 其他 fail
  - `checkRoutineCallArguments()` → 数量检查 → 逐参数类型 + VAR lvalue 检查
- **推荐工具**：Mermaid（可直接嵌入 markdown）或 draw.io
- **文件**：`images/04-semantic-type-check.png`
- **具体画法**（Mermaid）：
  ```mermaid
  flowchart TD
    A[类型检查] --> B{isNumericType?}
    B -->|Yes| C[promoteNumeric]
    C --> D{任一为 Real?}
    D -->|Yes| E[返回 Real]
    D -->|No| F[返回 Int]
    B -->|No| G{isBooleanType?}
    ...
  ```

  用 Mermaid Live Editor 渲染导出。

## 05 — 代码生成模块

### 图 5.1：generateTemplate() 主流程图

- **插入位置**：`### 主流程：generateTemplate()` 段落，替换 ASCII 流程图
- **图类型**：流程图（纵向）或泳道图
- **内容**：
  - 10 个步骤从上到下排列
  - 每步标注函数调用和返回的数据结构
  - 关键数据依赖用横向虚线连接（如第一遍扫描 → StatementContext → 第二遍扫描）

  1. 纵向排列 10 个矩形框
  2. 左侧标注步骤编号 1-10
  3. 框内写：函数名 + 返回类型
  4. 用粗线框突出步骤 3-10（核心转换逻辑）
  5. 两遍扫描之间用虚线箭头标注 `funcNames, routineByRef`

### 图 5.2：VAR 参数指针转换机制图

- **插入位置**：`### VAR 参数处理` 段落
- **图类型**：对比示意图（Pascal ↔ C）
- **内容**：
  - 左侧：Pascal 声明和用法（`var x: integer`、`x := 5`、`p(x)`）
  - 右侧：C 翻译（`int *x`、`*x = 5`、`p(&x)`）
  - 用箭头连接左右对应项
  - 三种场景分行展示：声明、读取（表达式内自动解引用）、写入（左值写指针）、传参（取地址）
- **推荐工具**：Excalidraw（手绘风格更适合概念对比）
- **文件**：`images/05-codegen-var-param.png`
- **具体画法**：
  1. 画 3 行 × 2 列的表格
  2. 左列 = Pascal 代码块，右列 = C 代码块
  3. 每行标注场景名（声明/写入/读取/传参）
  4. 用彩色箭头标注转换规则

### 图 5.3：Pascal → C 控制流映射表

- **插入位置**：`## 语句翻译` 章节后，汇总 7 种控制流翻译
- **图类型**：对照表示意图
- **内容**：
  - 表头：Pascal 语法 | C 语法 | 特殊处理
  - 7 行对应 if/while/for/repeat/case/read/write
  - 每行用两种颜色分别显示 Pascal 和 C 代码片段
- **推荐工具**：draw.io（用表格布局）或直接在 Markdown 中用 HTML table 并配截图
- **文件**：`images/05-codegen-controlflow-map.png`
- **具体画法**：
  1. 在 draw.io 中创建一个 8 行 × 3 列的大表格
  2. 行 1 为表头，行 2-8 为各控制流
  3. 代码块用等宽字体
  4. 特殊处理列用红色小字标注（如 "Pascal := → C =", "repeat → do-while + !条件"）
