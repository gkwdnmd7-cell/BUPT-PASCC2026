# 语义分析模块 (Semantic Declaration Analyzer)

## 模块职责

语义分析模块是编译流水线的第三阶段，在语法分析通过后对程序进行语义正确性检查。模块的核心职责包括四个方面：

1. **标识符声明检查**：检测标识符在被使用前是否已声明（"声明前使用"错误 S103），以及同一作用域内是否存在重复定义（S101）。
2. **类型兼容性检查**：对表达式中的运算符-操作数类型约束进行验证（如 `div` 操作数必须为 integer），对赋值语句的左右类型进行兼容性判断（如同类型直接兼容、Int→Real 宽度拓宽兼容）。
3. **过程/函数调用检查**：验证调用时的实参数量是否与形参数量匹配，实参类型是否与形参类型兼容（值参数允许 Int→Real 拓宽，VAR 参数要求类型完全一致），VAR 参数位置是否传入了可赋值的左值。
4. **控制流条件检查**：验证 if/while/repeat-until 的条件表达式类型为 Boolean。

语义分析器采用**独立递归下降**策略——不对 AST 做遍历，而是自己维护 Token 流游标逐 Token 前进，按 Pascal-S 结构递归下降分析。它拥有一套完整独立的符号表体系（包括类型系统、符号系统和作用域管理），与代码生成器的内部数据结构完全解耦。

## 符号表数据结构 UML

符号表体系是语义分析模块的核心基础设施。下图以完整 UML 类图展示类型系统、符号系统、作用域管理和内建类型池之间的继承与组合关系。

![符号表 UML 类图](picture/10-symbol-table-uml.png)

该图清晰揭示了以下关键设计：

### 类型系统（左上部分）

- **`TypeTemplate`** 是抽象基类，持有 `Kind` 枚举（`Basic`/`Array`/`Record`）。当前实现中只有 `BasicType` 子类被实际使用，`Array` 和 `Record` 的 Kind 值仅作为占位预留。
- **`BasicType`** 进一步通过 `BasicKind` 枚举区分 `Int`/`Real`/`Bool`/`Char`/`None` 五种基本类型。注意类型比较不是通过字符串名称而是通过枚举值——这是 O(1) 的类型等价判断。

### 符号系统（右上部分）

- **`ObjectSymbol`** 是抽象基类，持有 `name_`（标识符字符串）。
- **`VariableSymbol`** 通过组合关系持有 `shared_ptr<TypeTemplate>`，表示变量的类型引用。
- **`RoutineSymbol`** 持有 `RoutineKind` 枚举（`Procedure`/`Function`）、`parameters_` 向量（每个元素是 `RoutineParameter` 结构体，含 `byRef` 布尔和 `type` 指针）和 `returnType_`（仅函数有值）。
- **`RoutineParameter`** 通过组合关系持有 `shared_ptr<BasicType>`——注意参数类型被限定为 `BasicType` 而非 `TypeTemplate`，这意味着当前语义分析不支持数组/记录类型的参数。

### 作用域管理（左下部分）

- **`TableSet`** 是作用域管理的核心单元。每个 TableSet 代表一层作用域，包含 `symbols_`（`SymbolTableTemplate<ObjectSymbol>`，底层为 `unordered_map`）和 `defTypes_`（`TypeTable`，底层为 `unordered_map`）两张表。`prevSet_` 指针形成单向链表，指向外层作用域。
- `insert<T>(name, symbol)` 模板方法利用 C++17 的 `if constexpr` 在编译期自动分发：若 T 继承自 `TypeTemplate` 则写入 `defTypes_`，若继承自 `ObjectSymbol` 则写入 `symbols_`。
- `searchEntry<T>(name, &local)` 模板方法实现链式查找：先在当前层查询（`searchLocal<T>`），未命中则沿着 `prevSet_` 指针向外递归搜索。`local` 输出参数指示查询结果是否来自当前作用域（用于区分"同作用域内重定义"和"跨作用域覆盖"）。
- **`ScopeStack`** 持有 `vector<unique_ptr<TableSet>>`，拥有所有作用域层的所有权。`push(tag)` 自动将新作用域的 `prevSet_` 设置为栈顶，`pop()` 释放最内层作用域。

### 内建类型池（右下部分）

- **`BuiltinTypePool`** 持有四种内建类型（`integer_`/`real_`/`boolean_`/`character_`）的 `shared_ptr<BasicType>` 单例。`findByName("integer")` 通过哈希表查询返回对应类型的 shared_ptr，`installInto(TableSet*)` 将四种类型全部注入指定作用域（通常在全局作用域创建后立即调用）。

## 作用域链结构

作用域链是语义分析中标识符查找的核心数据结构。下图展示了三层嵌套作用域的链式关系。

![作用域链结构图](picture/04-semantic-scope-chain.png)

图中展示了三个作用域层纵向排列所形成的单向链表：最上层的 `global` 作用域（含内建类型 `integer`/`real`/`boolean`/`char` 和全局变量/例程符号），中层的 `procedure foo` 作用域（含局部变量和参数符号），下层的 `function bar` 作用域（含局部变量、参数和返回值）。每层通过 `prevSet_` 指针指向上层，形成从内向外的作用域访问路径。右侧标注的 `ScopeStack::current()` 指针始终指向当前最内层作用域（栈顶），而 `searchEntry()` 方法沿 `prevSet_` 链向外逐层查找。

### 子程序语义分析

```cpp
// semantic_declaration.cpp:224-264
parseSubprogram() {
    // 1. 判断 routineKeyword (Procedure/Function)
    // 2. 读取子程序名
    // 3. 在父作用域注册 RoutineSymbol（声明前使用检测在这里生效）
    //    declareRoutine():
    //      └─ scopes_.current()->insert(name, RoutineSymbol)
    //         └─ 若 insert 返回 false → S101 重定义错误
    // 4. scopes_.push(routineName) — 创建子作用域
    // 5. parseFormalParameters()
    //    └─ 为每个形参在子作用域注册 VariableSymbol
    //    └─ 构造 vector<RoutineParameter> 设置到 RoutineSymbol
    //    └─ VAR 参数: RoutineParameter.byRef = true
    // 6. 若为函数: 解析返回类型 → routine->setReturnType()
    // 7. match(Semicolon)
    // 8. parseBlock() 递归处理子程序体
    // 9. scopes_.pop() — 退出子作用域
    // 10. match(Semicolon) — 子程序声明后的分号
}
```

关键语义约束在此实现：第 3 步中**先在父作用域注册 RoutineSymbol，再进入子作用域**——这允许子程序体内部递归调用自身（函数名已在父作用域可见）。但这也意味着 Pascal-S 中不能在子程序定义之前调用它（这点与标准 Pascal 不同，标准 Pascal 允许前向声明）。

### 运算符类型约束汇总

| 运算符 | 操作数类型要求 | 结果类型 |
|--------|---------------|---------|
| `+`, `-`, `*` | 两边均为 numeric（Int 或 Real） | `promoteNumeric(lhs, rhs)` |
| `/` | 两边均为 numeric | 始终为 Real |
| `div`, `mod` | 两边均为 Integer | Integer |
| `and`, `or` | 两边均为 Boolean | Boolean |
| `not` | Boolean → Boolean；Integer → Integer | 与操作数相同 |
| `=`, `<>`, `<`, `<=`, `>`, `>=` | 两边同类型，或同为 numeric | Boolean |

### 赋值语句类型检查

```cpp
// semantic_declaration.cpp:601-636
parseIdentifierStatementSemantics() {
    auto sym = checkIdentifierUsage(identTok);  // S103: 验证标识符已声明
    if (跟 LParen) {
        // 过程/函数调用
        auto routine = dynamic_cast<RoutineSymbol>(sym);
        auto args = parseCallArguments();       // 推导每个实参的类型+左值性
        checkRoutineCallArguments(routine, args, tok.pos);  // S202: 参数匹配
    } else if (跟 Assign) {
        // 赋值语句
        auto lhsType = resolveVariableType(sym); // 左值类型
        auto rhsType = parseExpressionType();    // 右值类型
        if (!isAssignable(lhsType, rhsType)) {   // S201: 赋值类型不兼容
            // 报告类型错误
        }
    }
}
```

### 形参/实参匹配算法

```cpp
// semantic_declaration.cpp:942-972
checkRoutineCallArguments(routine, args, callPos) {
    // 1. 参数数量必须匹配
    if (args.size() != routine->parameters().size()) {
        → S202 "Wrong number of arguments"
    }
    // 2. 逐参数检查
    for (size_t i = 0; i < args.size(); ++i) {
        if (param.byRef) {
            // VAR 引用参数
            if (!args[i].isLvalue) → S202 "VAR parameter requires a variable"
            if (args[i].type ≠ param.type) → S202 "VAR parameter type mismatch"
            // 注意：VAR 参数要求类型完全一致，不允许 Int→Real 拓宽
        } else {
            // 值参数
            if (!isAssignable(param.type, args[i].type)) → S202 "Type mismatch"
        }
    }
}
```

`looksLikeVariableArgument()` 辅助函数（`semantic_declaration.cpp:801-837`）通过向前扫描 Token 流来判断一个实参是否具有变量形式（即不含运算符的单个标识符、不含括号的数组下标访问等），用于 VAR 参数的左值检查。

### 标识符查找

```cpp
// semantic_declaration.cpp:974-986
std::shared_ptr<ObjectSymbol> checkIdentifierUsage(const Token& tok) {
    bool local = false;
    auto sym = scopes_.current()->searchEntry<ObjectSymbol>(tok.lexeme, &local);
    if (sym == nullptr) {
        result_.errors.push_back(SemanticError{
            "S103", "Undefined identifier in use: " + tok.lexeme, tok.pos
        });
    }
    return sym;
}
```

`searchEntry<ObjectSymbol>()` 沿 `TableSet` 的 `prevSet_` 链向外搜索，无需显式遍历——链式查找被封装在 `TableSet::searchEntry()` 内部。

## 错误码体系

语义分析模块使用 `S1xx` 和 `S2xx` 两个系列的错误码：

| 错误码 | 含义 | 典型触发场景 |
|--------|------|-------------|
| S101 | 同一作用域内重复定义 | `var x: integer; var x: real;` 或 `procedure p; procedure p;` |
| S102 | 未定义的类型引用 | `var x: unknownType;` |
| S103 | 未定义标识符的使用 | `x := 5;` 但 x 未在 var 区声明 |
| S199 | 语法阶段未产出 AST 根 | `parseResult.root == nullptr`（不应发生，仅为防御性检查） |
| S201 | 类型不兼容 | 赋值左右类型不匹配、运算符操作数类型错误、条件表达式非 Boolean |
| S202 | 例程调用参数错误 | 参数数量不匹配、类型不兼容、VAR 参数传入非左值 |
| S102 | 未定义的类型 | [semantic_declaration.cpp:353], [937] |
| S103 | 未定义的标识符 | [semantic_declaration.cpp:983] |
| S199 | 语法阶段未产生 AST 根 | [semantic_declaration.cpp:19] |
| S201 | 类型不兼容 | 表达式/条件/赋值类型检查多处 |
| S202 | 例程调用参数错误 | 数量不匹配/类型不匹配/VAR 参数要求 lvalue |
