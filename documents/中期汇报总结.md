## 二、 核心模块设计细节（重点）

本编译器的整体架构采用经典的“前端-后端”流水线设计，将 Pascal-S 源码依次经过词法扫描、语法解析、语义检查，最终生成等价的 C 语言代码。以下是各核心模块的具体设计与技术决策细节。

### 2.1 词法分析器设计 (Lexical Analyzer)

词法阶段经历了从“纯手工 C++实现”到“Flex 自动生成”的架构演进，最终确立了**“Flex 核心 + C++ 适配层”**的设计模式。

- **规则收口与特性**：标识符不区分大小写，最大长度限制为 8 个字符；支持跨行注释（不支持嵌套）；字符常量仅支持单字符。
- **适配器模式 (Adapter Pattern)**：为了对齐评测平台的标准，底层扫描引擎切换为 Flex (`lexer_flex.l`)。但为了保持向上层提供稳定的 Token 流和错误接口，我们保留了 `Lexer::tokenizeDetailed` 的 C++ 适配层。
- **错误处理机制**：实现了精细化的词法错误分类（如 E105, E106 等），所有错误均携带精准的行列号定位信息。遇到严重词法错误时，编译器会以退出码 `7` 终止运行。

### 2.2 语法分析器设计 (Syntax Analyzer)

语法阶段采用 **Bison (YACC)** 作为解析主线，并负责构建抽象语法树（AST）。

- **AST 节点设计**：设计了轻量级的 AST 骨架，包含 `Program`、`Statement`、`Expression` 等基础节点，解析完成后 `ParserResult` 会携带完整的 AST 根节点向下传递。
- **错误恢复策略 (Error Recovery)**：采用了 **Panic Mode（恐慌模式）** 进行语法错误恢复。设定了明确的同步点（如 `;`, `end`, `)`, `]`, `.`）。
- **指标化容错**：为避免遇到语法错误就立刻崩溃，我们对错误恢复进行了指标化设计，设定单次编译最多容忍 50 个错误，并确保编译器能够连续输出多条语法错误（E201）而不中断解析，极大提升了编译器的鲁棒性。

### 2.3 语义分析器设计 (Semantic Analyzer)

语义分析是本项目的重难点。我们将其拆分为 6 个子阶段，并设计了严密的**门控机制 (Semantic Gating)**。

- **作用域与符号表 (TableSet)**：实现了基于栈的作用域管理（Scope Stack）。`TableSet` 支持父链向上搜索、局部作用域入栈/出栈。当作用域弹栈后，局部符号自动对外不可见。
- **类型系统池**：建立了基础类型常量池（`integer`, `real`, `boolean`, `char`），为后续的类型推导提供统一的内存单例。
- **多级语义检查流水线**：
  1. **声明检查**：拦截同层重定义 (S101) 和未定义类型声明 (S102)。
  2. **使用点检查**：拦截变量和过程的未定义使用 (S103)。
  3. **类型推导与赋值相容**：实现算术、关系、逻辑表达式的类型推导，并检查赋值相容性 (S201)。
  4. **参数匹配检查**：严格校验过程/函数调用的参数个数、值参类型（支持 `int` 到 `real` 的隐式提升），并强制要求引用参数 (`var`) 的实参必须为左值 (S202)。
- **语义失败门控**：在驱动层接入了语义门控逻辑。一旦语义分析阶段报错，编译器将立即返回退出码 `9`，并**强制禁止**后续 C 代码文件的生成。

### 2.4 代码生成器设计 (Code Generator)

代码生成阶段摒弃了脆弱的硬编码字符串拼接，采用了**结构化模板 (Template-based)** 的生成策略。

- **模板区段划分**：生成的 C 代码被严格划分为：运行时 I/O 帮助函数区（如 `pas_read_int`）、全局声明区、子程序声明区和主语句区。
- **控制流映射**：通过递归遍历 AST，将 Pascal 的控制流精准映射为 C 语言结构。例如 `for i := a to b` 映射为 `for (i = a; i <= b; ++i)`，`downto` 映射为递减循环。
- **子程序与参数映射**：
  - Pascal 的 `procedure` 映射为 C 的 `void` 函数；`function` 映射为带对应返回类型的 C 函数。
  - Pascal 中的引用参数 (`var`) 在 C 代码中被精准映射为**指针类型**。
  - 函数体内的返回值赋值 `func := expr` 被自动转换为 C 的 `return expr;`。
- **类型严格映射**：根据项目决策，Pascal 的 `real` 类型被严格、统一地映射为 C 语言的 `float` 类型，确保了浮点数运算的精度一致性。

## 三、 测试与质量保证体系

为了保证编译器的可靠性，我们建立了一套高度自动化的客观测试体系：

1. **自动化单元与集成测试**：基于 CTest 构建了 12 个测试套件，覆盖从词法冒烟测试到语义门控的全链路，目前回归测试通过率保持在 100%（12/12）。
2. **端到端批测脚本 (E2E Objective Script)**：编写了 PowerShell 脚本，支持“输入 Pascal -> 生成 C -> 编译 C -> 运行比对”的全自动闭环测试，并自动核验编译器的退出码（成功 0，词法错误 7，语义错误 9）。
3. **文法覆盖矩阵**：建立了详细的语法覆盖矩阵文档，将 Bison 产生式与测试用例一一对应，确保测试的客观量化。
